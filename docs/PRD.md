# PRD

## 1. 문서 개요

- 프로젝트명: healthcare-task-dashboard

## 2. 제품 목표

- 로그인, 대시보드, 할 일 목록, 할 일 상세, 회원정보까지 이어지는 기본 업무 흐름을 완성한다.
- 요구사항에 명시된 API 계약을 기준으로 삼는다.
- 접근성과 유지보수성을 함께 고려한다.

## 3. 사용자 시나리오

1. 사용자는 로그인 페이지에서 이메일과 비밀번호를 입력한다.
2. 로그인 성공 시 대시보드로 이동한다.
3. 사용자는 좌측 네비게이션으로 대시보드와 할 일 목록을 오간다.
4. 사용자는 할 일 목록에서 카드 클릭으로 상세 페이지에 진입한다.
5. 사용자는 상세 페이지에서 삭제 확인 절차를 거쳐 목록으로 되돌아간다.
6. 사용자는 회원정보 페이지에서 자신의 정보를 확인한다.

## 4. 라우트 설계

| Route | 목적 | 비고 |
| --- | --- | --- |
| `/` | 대시보드 | 인증 이후 진입 기본 화면 |
| `/sign-in` | 로그인 | 공개 페이지 |
| `/task` | 할 일 목록 | 가상 스크롤 + 무한 스크롤 대상 |
| `/task/:id` | 할 일 상세 | 404 예외 화면 필요 |
| `/user` | 회원정보 

## 5. 기능 요구사항

### 5.1 공통 레이아웃

- GNB/LNB에 다음 항목을 제공한다.
  - 대시보드
  - 할 일
  - 로그인 또는 회원정보
- 아이콘은 항목마다 겹치지 않게 사용한다.
- 색상은 CSS 토큰으로 관리한다.
- 폰트는 Pretendard를 사용한다.

### 5.2 로그인

- `/api/sign-in` POST 호출
- 입력 필드
  - 이메일: 필수, 이메일 형식
  - 비밀번호: 필수, 영문/숫자, 8~24자
- 유효성 검증 실패 시 필드별 메시지 노출
- 조건 만족 전 제출 버튼 비활성화
- 200 이외 응답 시 `errorMessage` 기반 오류 모달 노출

### 5.3 대시보드

- `/api/dashboard` GET 결과 표시
- 지표
  - 일
  - 해야할 일
  - 한 일

### 5.4 목록

- `/api/task?page=` GET 결과를 카드 목록으로 노출
- 카드 항목
  - title
  - memo
- 목록 요구사항
  - 가상 스크롤
  - 무한 스크롤
  - 카드 클릭 시 상세 이동

### 5.5 상세

- `/api/task/:id` GET 결과 표시
- 404 응답 시 예외 화면 및 목록 복귀 버튼 제공
- 삭제 버튼 제공
- 삭제 확인 모달 요구사항
  - id와 동일한 값 입력 시 제출 활성화
  - 제출 성공 시 목록으로 이동

### 5.6 회원정보

- `/api/user` GET 결과 표시

## 6. 기술 설계

### 6.1 프레임워크

- Next.js App Router 사용
- 이유
  - 라우트 단위 구조화가 명확함
  - 서버/클라이언트 컴포넌트 분리가 쉬움

### 6.2 상태 및 데이터

- 서버 상태: TanStack React Query
- 폼 상태: react-hook-form + zod
- 인증 토큰 전략
  - access token: 클라이언트 저장
  - refresh token: 쿠키 전제
  - 실제 리프레시 플로우는 `/api/refresh` 스펙 기준으로 구현

### 6.3 API mocking

- 개발 환경에서는 MSW 사용
- 목적
  - 별도 백엔드 없이도 API 계약 기준 개발 가능
  - 오류 응답과 예외 흐름 재현 가능
- 현재 스캐폴딩에 포함된 mock 범위
  - sign-in
  - refresh
  - user
  - dashboard
  - task list
  - task detail
  - task delete

### 6.4 구조 원칙

- `src/app`: 라우트 엔트리
- `src/features`: 사용자 액션 단위 기능
- `src/entities`: 도메인 단위 표현
- `src/widgets`: 페이지 조합 블록
- `src/shared`: 공용 API, UI, 설정, 모킹

## 7. 비기능 요구사항

- 접근성
  - 모든 입력 필드 label 제공
  - 페이지별 명확한 제목 유지
  - 키보드 포커스 스타일 제공
- 유지보수성
  - API 계약 타입 분리
  - 공용 UI 컴포넌트 분리
  - 색상 토큰화
- 성능
  - 목록 페이지에 가상 스크롤 적용
  - 무한 스크롤 시 필요한 항목만 렌더링

## 8. 자율 결정 및 가정

- 회원정보 페이지 라우트는 `/user`로 결정
- 로그인 이후 기본 이동 경로는 `/`
- 앱 전역 레이아웃은 로그인 페이지와 인증 이후 화면을 분리
- MSW는 `NEXT_PUBLIC_ENABLE_MSW=true`일 때만 활성화
- 현재 단계에서는 전체 구현 전, 구조와 진입 코드를 우선 구성

## 9. 구현 우선순위

1. 프로젝트 설정 안정화
2. 로그인 플로우 완성
3. 대시보드 API 연동
4. 목록의 무한 스크롤 및 가상 스크롤 완성
5. 상세 조회 및 삭제 플로우 완성
6. 회원정보 연동
7. 마감 전 접근성, 예외 처리, 제출 문서 정리

## 10. 완료 기준

- 요구된 라우트가 모두 동작한다.
- API 응답 성공/실패 케이스를 재현할 수 있다.
- 로그인 폼 검증과 오류 모달이 동작한다.
- 할 일 목록에 가상 스크롤과 무한 스크롤이 적용된다.
- 상세 404 처리와 삭제 확인 절차가 동작한다.
- 색상 토큰, Pretendard, 아이콘 규칙이 지켜진다.
- `AI_USAGE.md`와 프로젝트 문서가 제출 가능한 수준으로 정리된다.
