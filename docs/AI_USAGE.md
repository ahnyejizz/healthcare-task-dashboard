# AI_USAGE.md

## 1. 사용 사실

요구사항 분석, 문서 초안 작성, 코드/구조 검토, 구현 아이디어 정리 등 보조 용도로 사용했으며
최종 결과물의 선택과 수정, 검증은 직접 수행

## 2. 사용한 도구 / 모델

- 도구: Codex
- 모델: GPT-5 계열 코딩 모델

## 3. 적용한 작업 범위

- [docs] 전체 구현 범위를 해석하고, 우선순위와 작업 단위를 정리
- [feat] Next.js App Router, FSD 구조, 공통 UI, API 레이어, MSW 모킹 구조 등 프로젝트 기본 아키텍처를 구성하거나 정리하는 작업에 활용
- [feat] 로그인, 대시보드, 할 일 목록, 할 일 상세, 회원정보 등 주요 화면 구현 과정에서 필요한 컴포넌트 구조와 데이터 흐름 정리에 활용
- [feat] 폼 검증, 인증 흐름, 목록/상세 조회, 삭제 확인, 예외 처리 등 기능 구현 시 필요한 코드 초안이나 리팩토링 방향 정리에 활용
- [refactor] 중복 로직 정리, 공통 유틸/공통 UI 분리, 컴포넌트 책임 분리, 불필요한 로직 제거 등 코드 단순화와 구조 개선 작업에 활용
- [docs] 문서 작성 시 저장소 내 기존 문서 톤과 맥락을 참고하여 `AI_USAGE.md` 초안과 항목 구성을 정리하는 데 활용

## 4. 핵심 프롬프트 요약

- 요구사항을 기준으로 PRD를 작성해 달라고 요청
- 라우트 구조, 화면 단위, 공통 컴포넌트, API/상태 관리 구조를 현재 프로젝트 스타일에 맞게 구성하거나 정리해 달라고 요청
- 코드가 과도하게 복잡해지지 않도록 className, props, 상태 분기, 추상화 수준을 점검해 달라고 요청
- 중복되는 로직은 공통 유틸이나 공통 UI로 분리하고, 역할이 과하게 몰린 파일은 적절히 나누는 방향으로 개선해 달라고 요청
- 사용하지 않는 변수, 함수, 상태값, 불필요한 분기나 미사용되는 로직이 없는지 점검해 달라고 요청

## 5. 사람이 최종 검증한 내용

- AI의 초안이나 제안을 그대로 반영하지 않고, 가독성, 유지보수성, 요구사항 적합성을 기준으로 직접 수정하거나 추가 요청이 필요한 부분을 재정리
- 같이 일하는 현업 개발자가 보기에 바로 이해할 수 있도록 불필요하게 긴 className, 과도한 props 등은 더 직관적이고 단순한 형태로 정리
- 사용되지 않는 변수, 함수, 상태값, 분기 처리 등 미사용되거나 불필요한 로직이 남아 있지 않은지 점검
- 여러 곳에서 반복되는 로직은 공통 유틸, 공통 함수, 공통 UI로 분리할 필요가 있는지 검토
- 하나의 컴포넌트나 파일에 역할이 과하게 몰린 경우에는 화면, 상태 처리, UI 조각 등을 나누어 책임 분리
- 문서에 민감정보(API 키, 개인/회사 비밀정보)가 포함되지 않았는지 확인
- 요구사항의 필수 항목이 모두 포함되었는지 확인
- 최종 문서 형식 검토
